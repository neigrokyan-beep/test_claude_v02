# Studio Bridge — правила для облачной сессии

Пользователь — Максим, 3D-моушн-дизайнер. Общение по-русски, коротко, без воды.
Этот репозиторий — мост из облака к его ПК (Windows): Cinema 4D, Houdini, Fusion, Nuke,
хранилище Obsidian «Weaver» и библиотека материалов Greyscalegorilla (GSG).
Код моста — `studio-bridge/`, инструкция — `studio-bridge/README.md`.

## Как работать

1. Начало: `bridge_status` — что подключено. Потом `weaver__weaver_context` — вход в хранилище
   (START, STATE, MAP, PROJECTS). По задаче — сначала её `Context.md` и карточка (`weaver__vault_read`).
2. Файлы ПК напрямую недоступны: хранилище — через `weaver__vault_*`, библиотека GSG — через `weaver__gsg_*`,
   картинки — `weaver__view_image` / `weaver__gsg_preview`.
3. **Материалы для сцены всегда из библиотеки GSG**, в тему проекта: `gsg_guide` (что где) → `gsg_find` /
   `gsg_collection` / `gsg_sheet` → `gsg_preview` (посмотреть) → `gsg_show` (карты, параметры, пути).
   Нужного нет — спросить пользователя или сделать самому.
4. В Cinema 4D материалы Redshift собирать готовыми загрузчиками из хранилища, а не писать заново:
   `Projects/claude/Server_motherboard/C4D/src/sm_mats.py` (`gsg_dir`, `gsg_maps`, `_gsg_make`, `replace`) и
   `Projects/claude/Yogo_pro_keyboard/C4D/src/ykb_gsg.py` (`make(doc, name, code, tile, space, tint, sss)`).
   Прочитать их `vault_read`, запускать через `c4d__execute_python_script`.
5. Закончил кусок — строка в «Состояние» `Context.md` задачи: `ГГГГ-ММ-ДД · Claude (облако) — что сделано`;
   какой материал взят и почему (код, плитка, оттенок) — в «Решения».

## Что уже роняло софт (соблюдать)

- **C4D**: в выводе Python (`print`) только ASCII — кириллица и «—» рвут мост и закрывают C4D.
  Не вызывать `RenderDocument` пачкой, а с Redshift — никогда. Рендер — только по просьбе, по одному кадру, через
  Picture Viewer. Не сохранять «активный» документ (28.09 так записали пустой Untitled поверх сцены);
  свой документ искать по имени.
- **C4D, тяжёлые сцены (Yogo, 29.09)**: `GetRad`/`GetMp`/`GetCache` и обход геометрии у SDS-мастеров и инстансов (`MASTERS`, `SWITCHES`) вешают C4D, а после этого он падает. Габариты в таких сценах не запрашивать. Работать только с трансформами (`GetRelPos`, `GetMg`), треками и тейками. Перед любым скриптом, который обходит больше нескольких объектов, сцена должна быть сохранена.
- **Houdini**: рендер Redshift в открытой сессии уронил Houdini — рендерить отдельным `hython`, в открытой сессии
  только лёгкое. Невыросшую геометрию удалять, не стягивать в точку.
- Файл, открытый в C4D или плеере, не переносится — пропустить и назвать.

## Чего не трогать

- Библиотеку GSG — только чтение. Старую библиотеку Eagle, `Eagle_lib/`, заметки `Library/tutorial/Houdini`.
- Ничего не удалять: лишнее и оригиналы перед правкой — в `Agent/History/<ГГГГ-ММ-ДД>/`
  (`vault_write` с `overwrite` делает копию сам).
- Ссылка коннектора и токен — секрет: не выводить в чат и не коммитить.
